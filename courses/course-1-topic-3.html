Course 1 · Topic 3 of 6

Specify variables and design the instrument

Reading time: about 4 minutes

In this topic

Revise an AI-drafted extraction or interview specification so that its questions, variables, allowed responses, and rules for missing values are clear.

For your project: you link each question in the question bank to a variable in your first data dictionary, before collecting anything.

Key terms
Variable
A field with a written definition: what it means, which records it applies to, and what values it can take.
Instrument
The set of questions or extraction instructions used to collect information, such as an interview guide.
Allowed responses
The values a variable may take, such as a date in a set format or a short list of codes.
Missing-value rule
What to do when the information is not there: leave the cell empty and record the reason.
Leading question
A question that assumes its own answer, for example by assuming that someone failed.
Data dictionary
A table that defines every variable so another person can interpret the data.

A field name is not a definition

“Appointment date” could mean the day someone booked the appointment, the planned visit date, or the day the visit actually happened. An extraction can copy a date perfectly and still put it in the wrong field.

Before collecting values, write a plain-language definition, name the eligible records, state what one row represents, and specify the allowed responses. This makes the instruction useful both to the AI and to the student who receives the dataset.

Problem 2: two different dates

Source statement

“2026-10-09: Appointment booked for 2026-10-16.”

event_date
The date of the recorded action. Here, the booking: 2026-10-09.
planned_visit_date
The future or intended visit date stated in the same statement. Here: 2026-10-16.

Write dates as year-month-day, as the teaching sources already do. Do not invent a time of day. Keep the source wording next to the extracted fields so a reviewer can check your interpretation. The period the source covers and the date you collected it remain separate details.

Problem 1: evidence status

The instructor supplies a teaching checklist, not a clinical referral standard. For each packet, ask whether the material available at the first review supports three items: the destination service, a callback route (how to contact the sender), and an administrative handoff summary. Record the answer with one of three codes:

Evidence-status codes for Problem 1
CodeMeaning
SUPPORTEDPresent in the supplied material.
NOT_FOUNDNot found in the supplied material. It does not mean the service never happened or that the document exists nowhere.
UNCLEARThe material is not enough to interpret.

Use a separate review decision to record whether you accept, correct, or reject what the AI extracted. Topic 5 covers this.

Problem 3: neutral questions

Draft neutral questions about what starts the work, what information is needed, how receipt is confirmed, and who follows up.

Leading

“Why does the receiving team fail to follow up?”

It assumes both a failure and an owner.

Neutral

“Who checks receipt when no acknowledgment arrives?”

It asks about the process.

Ask AI to improve the wording, then keep the approved question text and link it to the variable reported_followup_owner. An answer describes one person’s account. Putting it in a table does not turn it into an observed workflow or an approved assignment.

How this connects to DDI

The course’s documentation approach links an instrument, a question, a variable, the eligible records, and how values are written. The DDI standard has structures for instruments and questions, and its description of a variable includes the linked question, the records it covers, the unit of analysis, and how values are represented. We use these ideas as a small spreadsheet, not a full standards implementation. AI tool names, prompt versions, and local review codes are extra project fields, not official DDI elements [2].

Review the AI’s draft before using it

  • A missing number or date stays empty, with the reason stored separately. Never replace it with zero or a likely-looking date.
  • Where a source contains two unresolved alternatives, keep each supported statement and flag the conflict.
  • Save stable question and variable identifiers, so the prompt, the collected table, and the dictionary all refer to the same things.
  • Reuse correct definitions already in the workpad instead of creating new names for the same meaning.

AI instruction for this stage

Prompt to adapt: draft the instrument

Draft an instrument for the selected task. Return instrument ID, question or extraction-instruction ID, exact wording, linked variable ID, definition, eligible records, record unit, type or unit, allowed responses, and missing-value rule. Use the supplied checklist and source definitions. For P3, write neutral questions and do not answer them. Mark all proposed definitions for student review.

Practice activity

Try it: Workpad B

Review one question-to-variable link in Workpad B. Correct any unclear date, record unit, leading question, or unsupported response rule.

Check your understanding

A source says “2026-10-09: Appointment booked for 2026-10-16.” What belongs in event_date for the booking action?

  1. 2026-10-16
  2. 2026-10-09
  3. Either date, because both describe the appointment.
Show the answer

Answer: B. The action was recorded on October 9. October 16 is the separate planned visit date.

Use the variable definition, not the general topic of the sentence. A planned appointment date is not evidence that a visit took place.
