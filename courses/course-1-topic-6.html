Course 1 · Topic 6 of 6

Package the handoff for Course 2

Reading time: about 5 minutes

In this topic

Put together a versioned collection package that another learner can interpret, trace, and continue in Course 2.

For your project: you deliver the collection plan, sources, captured records, first data dictionary, and review notes as one reusable supporting artifact.

Key terms
Handoff package
Everything the next person needs to use your data: plan, sources, definitions, records, and notes, linked by stable IDs.
README
A short note at the front of a package that says what it contains and how to use it.
Curation
Course 2’s work: standardizing, checking, and combining data so it can be analyzed.
Version
A label, such as v1, that tells one saved state of the package apart from later edits.

The goal: a handoff someone else can interpret

Collection does not end with a spreadsheet in which every cell is filled. It ends with a handoff that another person can understand without guessing. Course 2 needs to know the task, what the records represent, how the information was captured, where the evidence is stored, and which issues remain open.

The same information supports your team’s evidence section and supporting artifact. It is not an extra final report on top of the proposal, the supporting analysis or demonstration, and the presentation that the program already requires.

What goes in the package

  1. The task and capture plan.
  2. The source catalog and the original materials.
  3. The question-to-variable links and the first data dictionary.
  4. The captured records and the reviewed copy.
  5. The AI-use, review, and handoff notes.

These parts can share one workbook or editable document. You do not need to complete every tab of the larger planning toolkit. Use stable identifiers to connect the parts instead of repeating a long source description in every row. Shared details can sit once in a clearly labeled source or run header.

The full list, with what each part must contain, is in Case materials.

Example: the event problem

  • The dictionary explains that one row is one event statement, and defines event_date and planned_visit_date separately.
  • The source catalog names the synthetic log, its version, and its cutoff date.
  • The collection record names the source input and prompt actually used.
  • The reviewed table keeps the supporting lines.
  • The issue list records the unresolved planned dates and the missing completion evidence.

Together, these let another student tell a well-supported statement apart from a complete history of the referral.

Record what AI contributed, stage by stage

A prompt used to draft a question is different from a prompt used to extract records. For each stage where AI helped, record the tool, the model name shown (if any), the date, the prompt version, the input sources, and where the output is saved. Keep the unedited output and the reviewed version.

If a stage used the instructor’s constructed draft, label it “no live run.” Do not invent a run log, and do not claim that a successful classroom check shows how accurate a product is in general or that a clinic’s work improved.

Check the links and scope before handoff

  • Every substantive field has a definition, or an open issue saying the definition is unresolved.
  • Every accepted value can be traced to its source.
  • Missing information and conflicts have reasons and proposed next actions.
  • Packet-item records, event statements, and role accounts stay in their own tables.

Matching column labels do not make a valid join. Course 2 will standardize the working data, check duplicates and compatibility, document changes, and decide how tables can be used together.

The handoff test

Ask another learner to:

  1. say what one row means;
  2. find a selected value in its source;
  3. explain a missing value;
  4. state what AI did.
Local handoff statuses
StatusUse it when
READY_FOR_CURATION_WITH_ISSUESThe package is understandable but has documented limitations.
RETURN_FOR_DOCUMENTATIONEssential meaning or traceability is missing.

These are local teaching statuses, not DDI standards. The goal is a defensible starting point for curation, not an early claim that the data are ready for analysis or that the referral problem is solved.

AI instruction for this stage

Prompt to adapt: check the package and draft a README

Inspect the collection package against its handoff checklist. Identify missing definitions, broken question-to-variable or source links, undocumented changes, and hidden gaps. Draft a short README stating task, scope, record unit, files and versions, AI contribution, unresolved issues, and next-course actions. Use only the package; mark missing details instead of inventing them. Do not claim DDI XML conformance or analysis readiness.

Check the AI’s README against the package. Do not accept invented reviewer names, missing file links, or a statement that every issue is resolved.

Practice activity

Try it: Workpad D and the handoff test

Complete Workpad D and run the handoff test with another learner. Save a versioned package for Course 2, with one clear limitation and the next action.

Check your understanding

Which package is ready to begin Course 2 curation?

  1. A polished table without sources or definitions.
  2. A source-linked table with definitions, preserved originals, documented AI use, and an open conflict that is clearly recorded.
  3. A table in which AI filled in all the unknowns.
Show the answer

Answer: B. A visible unresolved issue can be carried forward when meaning and traceability are clear.

A hides how the values were obtained. C disguises uncertainty as evidence. Ready for curation is not the same as complete, or ready for analysis.
